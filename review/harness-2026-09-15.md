## Open Source Defect

### P2: PowerShell launcher hides native CLI failures

Owner: [harness-runner.ps1](../skills/planning/harness/scripts/harness-runner.ps1),
`Invoke-HarnessProcess`.

- Evidence: the source launches `.ps1` shims with `pwsh -File`. A session probe returned
  `ExitCode: 0`, empty stdout, and stderr saying the configured 25-credit limit requires
  at least 30. The harness consequently reported `Invalid development result envelope`
  instead of the actual CLI startup error.
- Fix: invoke the shim through a wrapper with explicitly splatted arguments and propagate
  `$LASTEXITCODE`; return nonzero for PowerShell failures too. Preserve stderr and the
  existing child-only environment cleanup. Port only this change, not the whole installed
  runner, because the source contains newer unrelated changes.
- Verify: use a temporary shim whose native child emits stderr and exits 23; assert exit 23
  and retained stderr. Also test exit 0, argument preservation, and failure before JSON
  parsing on supported PowerShell versions. No live agent or schedule is needed.
- Status: fixed in the DaaP installed copy; real CLI failure/success checks passed there.
  Current SkillVault source still needs the fix and regression coverage.

## Skill Issue: Hard-Coded Worker Restrictions

Owner: `Invoke-HarnessAgent` in the shared runner.

- Evidence: with `--no-auto-login`, the worker reported missing authentication despite a
  successful login command. Removing that flag reached model validation, which rejected
  `gpt-4.1`. The CLI then rejected `model auto` combined with explicit `reasoning-effort max`.
- Fix: do not suppress normal authentication lookup. Support approved `model: auto` with
  `reasoningEffort: auto` and `--auto-tier intelligence`, without the effort flag. Offer an
  explicit full-development-access option instead of unconditional tool/MCP/path restrictions.
  Preserve read-only reviews, task scope, credential protection, and separately approved budgets.
- Earlier status: applied to the DaaP installed runtime and PACS configuration; a real no-tool
  startup probe passed there. The current source now supports inherited/native allowances,
  intelligence-oriented auto routing, and native credential lookup without `--no-auto-login`.
  It adds no allow-all grant and preserves explicit restrictions and read-only review isolation.
  Source behavior is covered by fixtures, not a live PACS run; T-001 remains unverified here.

## Implemented: Folder-Based Controllers

- Earlier restriction: `Get-HarnessWorkspace` required the controller's `ProjectPath` to be the
  coding Git root. A non-Git documentation/controller folder could initialize but not develop.
- Fix: register existing local Git roots through `/hn-ref`, then bind tasks with `-RepositoryRef`
  (`-RepoRef`). Controller state, board, reports, locks, and relative policy roots stay separate
  from current/worktree coding, validation, and review. Requirements Source is not the coding target.
- Boundaries: no cloning, implicit reference choice, Git initialization, permission expansion,
  or saved-task retargeting. Standalone review selects a project-wide reference; task-linked tests
  reuse the selected repository/workspace. Controller locks do not serialize other controllers.
- Verified: focused harness/test-flow/PR tests and the full suite passed, including 47 catalog
  entries. Fixtures cover invalid references, worktree ownership, repository-specific history,
  instruction context, complete development phases, and model-free tests. No live agent ran.
- Installed: seven affected project bundles and the existing global `harness-init` were refreshed
  in place and verified against source. Other project copies, live state, and schedules were untouched.
- Usage: [runtime contract](../skills/planning/harness/references/runtime.md#folder-controllers-and-coding-repositories).
